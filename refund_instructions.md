# Інструкція: Як робити повернення коштів клієнтам через KeyCRM

Ця інструкція описує процес оформлення автоматичних та ручних повернень коштів покупцям безпосередньо з інтерфейсу KeyCRM. Система підтримує повернення через два різні рахунки ФОП (ПриватБанк та LiqPay).

---

## 1. Загальні вимоги до замовлення

Щоб система змогла успішно провести повернення коштів, у замовленні **обов'язково** мають бути заповнені певні кастомні поля.

### Для повернення через **ФОП 1**:
1. **Тип оплати ФОП 1** (`OR_1047`) — оберіть потрібний рахунок ФОП зі списку.
   > *Примітка: Якщо оплата була через LiqPay, система може спробувати визначити цей рахунок автоматично, але краще завжди вказувати його вручну.*
2. **Повернення сума ФОП 1** (`OR_1038`) — вкажіть точну суму, яку необхідно повернути (тільки цифри, наприклад `1500`).

### Для повернення через **ФОП 2**:
Якщо вам потрібно зробити повернення з іншого рахунку:
1. **Тип оплати ФОП 2** (`OR_1060`) — оберіть потрібний рахунок ФОП.
2. **Повернення сума ФОП 2** (`OR_1059`) — вкажіть суму до повернення.

> [!TIP]
> **Одночасне повернення (ФОП 1 + ФОП 2)**: Якщо в замовленні заповнені суми для обох ФОП (наприклад, передоплата на ФОП 1 та залишок на ФОП 2), система коректно опрацьовує обидва платежі. Якщо один із ФОП уже було повернуто раніше, система автоматично виконає повернення для другого ФОП і збереже коментарі у відповідні поля (`OR_1046` для ФОП 1 та `OR_1080` для ФОП 2).

---

## 2. Додаткові поля (залежить від типу платежу)

Залежно від того, яким банком / шлюзом робиться повернення, потрібно заповнити додаткові реквізити.

### 🔹 Повернення на реквізити (ПриватБанк за IBAN)
Якщо повернення здійснюється як банківський переказ на картку/рахунок клієнта, необхідно **обов'язково** заповнити:
- **Повернення IBAN клієнта** (`OR_1039`) — формат `UAXXXXXXXXXXXXXXXXXXXXXXXXX`.
- **Повернення ЄДРПОУ клієнта** (`OR_1043`) — ІПН (РНОКПП) клієнта (10 цифр).
- **ПІБ покупця** (у стандартному блоці покупця в KeyCRM).

### 🔹 Повернення через LiqPay
Якщо оригінальна оплата була здійснена через LiqPay, кошти повертаються на ту саму картку, з якої була оплата. Для цього система повинна знайти ідентифікатор платежу.
Переконайтеся, що одне з наступних полів містить ID платежу:
- **Коментар покупця** (має містити текст формату `LIQPAY ID 123...` або `SOID ...`).
- **payment order id** (`OR_1034`) — поле з прямим ідентифікатором замовлення LiqPay.
- В одному з платежів до замовлення в описі є ідентифікатор `SOID ...`.

#### ✉️ Автоматична розсилка квитанцій LiqPay:
- Одразу після успішного проведення повернення LiqPay через API (`refund`), система автоматично відправляє **офіційну банківську квитанцію LiqPay на Email клієнта** (якщо пошта заповнена у блоці покупця KeyCRM або вказана у коментарі).
- У поле коментаря повернення (`OR_1046` / `OR_1080`) додається **помітка** про відправку (наприклад, `[Квитанцію надіслано на email: client@gmail.com]`), а також **посилання на офіційну перевірку квитанції**: `https://pb.ua/check`.
- За потреби менеджер може переглянути, роздрукувати або повторно відправити квитанцію на будь-яку пошту через сторінку `liqpay_receipt.php?order_id=[НОМЕР]`.

#### ✉️ Ручна відправка квитанції LiqPay:
Якщо на момент повернення у замовленні не було пошти або клієнт попросив надіслати квитанцію на інший Email:
1. Відкрийте сторінку **`https://[ваш-домен]/liqpay_receipt.php`** (кнопка також є в `manual_refund.php`, в `liqpay_logs.php` та на головній `index.php`).
2. Введіть номер замовлення KeyCRM або SOID.
3. Система підтягне суму повернення, картку, статус та email з замовлення (якщо є).
4. Введіть потрібний Email клієнта та натисніть **"Надіслати"**.
5. LiqPay згенерує банківську квитанцію та надішле її на цю пошту.
6. Система автоматично оновить помітку в замовленні KeyCRM: `[Квитанцію надіслано вручну на email: client@gmail.com (ДД.ММ.РРРР ГГ:ХХ)]`.

### 🔹 Повернення через Monobank (Еквайринг)
Якщо оригінальна оплата була здійснена через еквайринг Monobank, повернення здійснюється через API скасування оплати інвойсу (`/api/merchant/invoice/cancel`) на ту саму картку клієнта, з якої здійснювалася оплата.
Для цього:
1. Оберіть відповідний рахунок Monobank у полі **Тип оплати ФОП 1** (`OR_1047`) або **ФОП 2** (`OR_1060`) (система також вміє визначати його автоматично за способом оплати).
2. Вкажіть суму повернення у полі **Повернення сума** (`OR_1038` або `OR_1059`).
3. Система автоматично знаходить номер інвойсу Monobank (`invoiceId`):
   - З коментаря покупця (поле **Коментар покупця**, наприклад `260806F9cW3qPrAViYWa` або `invoiceId: ...`);
   - З поля **payment order id** (`OR_1034`);
   - З прив'язаного платежу в KeyCRM (`transaction_uuid` або опис платежу).
   *(Якщо поле порожнє, обов'язково вкажіть invoiceId у полі `OR_1034` або в коментарі).*
4. Заповнювати IBAN та ІПН для Monobank **не потрібно** (повернення зараховується безпосередньо платіжною системою Monobank).

## 3. Запуск процесу повернення

Процес повернення можна запустити двома способами:

### Спосіб А: Автоматично (через статуси)
1. Заповніть всі необхідні поля (ФОП, Сума, IBAN, ІПН).
2. Збережіть замовлення.
3. Переведіть замовлення в один зі статусів повернення (наприклад, статуси "Повернення", "Відмова" тощо, які налаштовані у системі).
4. Кожні декілька хвилин фоновий процес (CRON) автоматично знаходить такі замовлення і проводить виплату.

### Спосіб Б: Вручну
Якщо вам потрібно провести повернення негайно або без зміни статусу:
1. Заповніть і збережіть усі необхідні поля в KeyCRM.
2. Відкрийте посилання: `https://[ваш-домен]/manual_refund.php`
3. У таблиці "Останні замовлення на повернення" знайдіть ваше замовлення і натисніть кнопку **"Запустити"**.
4. Або просто введіть номер замовлення в поле вводу і натисніть "Запустити".
5. Ви одразу побачите результат виконання на екрані.

---

## 4. Контроль та результати

Після спроби повернення, система автоматично запише результат у кастомні поля самого замовлення в KeyCRM:

- **Повернення статус** (`OR_1042`) — зміниться на `SUCCESS` у разі успіху, або `ERROR` при помилці.
- **Повернення коментар** (`OR_1046`) — деталі платежу або текст помилки (якщо повернення було через ФОП 1).
- **ФОП 2 Повернення коментар** (`OR_1080`) — деталі платежу або текст помилки (якщо повернення було через ФОП 2).

> [!TIP]
> **Захист від дублювання**: Якщо поле статусу стоїть у `SUCCESS`, система **ніколи** не здійснить повернення за цим замовленням повторно. Також система перевіряє, чи не поверталася вже точно така сама сума за цим замовленням раніше (навіть якщо хтось видалить статус SUCCESS).

### Що робити при помилці (`ERROR`)?
1. Прочитайте текст помилки у полі коментаря (наприклад, "Невірний IBAN" або "Відсутнє поле ІПН").
2. Виправте дані клієнта або суму в замовленні.
3. Очистіть (зробіть пустими) поля **Повернення статус** та **Повернення коментар**.
4. Збережіть замовлення і знову переведіть його у статус повернення, або запустіть процес через `manual_refund.php`.
